# 理论探索进展

先遵循 [共同汇报方法](report.md)。本场景解释数学结果，不自动启动新推导、审查或文稿写作。

## 选择能改变判断的结果

从当前陈述、相关证明段落和已有审查中核对版本、假设及覆盖范围。只讲对本次问题关键的结果，按它解决了什么组织，而不按文件、worker 或证明完成顺序罗列。

区分文献结论、新推导、依赖其他结果的推论、已核结论、草图、观察和猜想。增加条件、缩小问题类或更换指标后，明确保留这个限制。整理旧材料不是新证明；模型审查、数值检错与形式化证明也不是同一种证据。

## 从直觉到必要公式

先说明结果回答什么问题，再给承载答案的公式，并就近定义必需的量。保留影响判断的参数、噪声、访问方式、成本、量词和输出指标。不要为了好看的速率隐去质量参数，或让读者经过一串辅助定义才能看到结论。

用一句话说明每个关键假设要求什么，及其对结果的作用；有依据时给出成立的例子或检验方法。证明思路只展开解释机制所需的步骤。用户要求严格定理或完整证明时，才进一步展示相应层次，不省略其承重条件。

正式数学文档的陈述与展示遵循 [doc-math](../../doc-math/SKILL.md) 及其 [展示规范](../../doc-math/references/research-presentation.md)。普通聊天不强制给所有公式编号，不因出现一个公式就加载整套论文写作规则。

## 说明结论的实际含义

分清数学正确性、假设适用性和研究价值：条件推出某速率，不等于真实应用满足条件；充分条件不满足，也不等于不可能改进。保留期望与概率、局部与全局、类级最坏情况与单个实例、有限时间与渐近的区别。

比较已有结果时先对齐条件与成本，指出真正多知道了什么。没有查新依据不宣称新颖性。只突出当前最关键的缺口及其影响；必要时给下一项决定性检验，避免把每个辅助引理都变成下一轮目标。

已有明确授权的审查可按其范围使用 `mathbox:proof-audit`；普通说明不自动重审未变化的证明。完整证据留在原有材料，回复保留必要结论与定位。
