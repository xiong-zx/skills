# Timing, one active script and optional Presenter Notes

## Plan a budget that can be rehearsed

Recover the actual speaking slot and whether it includes introductions, questions or discussion. Reserve appropriate time for pauses, slide changes, interpreting figures/equations and the ending. Allocate by explanatory difficulty and purpose, not equal seconds per page or a fixed slides-per-minute ratio.

Count the actual read-aloud text only. Exclude headings, navigation, delivery cues, technical notes, references and unused backup passages. Identify the counting unit: English words, Chinese characters or another justified unit. Mathematical symbols do not directly measure speaking time; account for the explanation actually to be spoken. Do not apply an English words-per-minute rate to Chinese character counts.

Prefer a measured pace from this speaker and comparable material. Otherwise give a clearly provisional pace range with its assumption and resulting budget; no speaking rate or talk duration is a universal default. For an initial English planning scenario, the University of Kansas text discusses roughly 100–150 words per minute; this is orientation, not a technical-talk standard, a target to hit or evidence of this author's pace.

One planning model is:
- usable speech time = slot minus separately budgeted Q&A, non-speaking pauses, visual inspection and slide changes;
- provisional word budget = usable speech time times assumed speaking-only rate.

Spoken transition sentences count as script words. If the measured rate already includes pauses and slide changes, do not subtract them again. An elapsed-time estimate should show which convention it uses. Reconcile the total with the section targets; state whether timing is estimated, measured from an actual author run, or unknown. A text count, silent reading or synthetic voice does not establish the author's delivery time.

When the draft is too long, cut redundant setup and secondary explanations before essential conditions or the conclusion. Offer specific optional passages or a shorter route, preserving prerequisite definitions and a coherent path. Keep current slide order by default; proposing skipped slides or reordering is separate from silently changing the deck.

## Check the words as speech

Read the draft as a listener who cannot reread the previous sentence. Check difficult phrasing, abstract noun stacks, breathless clauses, broken or overused transitions, ambiguous "this/it/they", unexplained terms, reading bullets twice, missing figure orientation and sudden conclusions. Repair the smallest coherent passage and preserve working author phrasing.

Check that the beginning, central result and ending fit the plan without rushing. Distinguish a text-based speakability/timing check from an aloud rehearsal with observed time. If a real recording or timed run is supplied, report only the measured material and conditions; a partial run does not validate the whole talk. Rehearsal recording, transcription or a new voice service is optional work, not a default requirement.

## Maintain one active script

Before writing a file, locate the existing active script and author edits. Update it in place when authorized, keeping the project's filename and history conventions. If none exists and a saved deliverable was requested, create one appropriate script file, not a separate file per page or revision.

Use the latest saved deck/outline and current author comments as inputs. Retain slide locators and source identity in the script's existing navigation or metadata when useful; hidden backups are not automatically part of the main spoken route. If the outline, deck and script disagree materially, identify the conflict before guessing the intended scientific content.

Preserve author additions and historical evidence through existing versioning/archive conventions. Do not generate extra revision, handoff, timing-report or duplicate script files solely to organize a change. Shorter passages can be marked in the same script; do not maintain two competing active scripts.

## Synchronize Presenter Notes only within authorization

A script-writing request alone does not authorize changing a PPTX. When the user requests notes synchronization, use the same current script as the content source. Do not separately regenerate notes that drift from it.

Before deck access or a notes edit, read [doc-slides technical workflow](../../doc-slides/references/technical-workflow.md) and use the verified local capability. If it or a suitable deck-editing capability is unavailable, deliver the script and report notes synchronization as unperformed; do not install or improvise a bridge. Confirm the exact saved deck, slide order/count, hidden slides and note-to-slide mapping. Slide titles may be duplicated; use inspected slide identities/indices. Keep one writer across sessions and clients; resolve unsaved author work rather than overwriting it.

Read existing notes first. A notes-set operation may replace the whole text: merge the script with author reminders, citations and Q&A material, preserving their separate non-spoken role. Use an existing managed script section if present; otherwise choose a minimal clear separation without deleting original notes. Surface a real conflict rather than replacing authored material silently.

Where available, use the inspected ppt-mcp notes read/set tools with the exact presentation path on every bound call. Discover schemas rather than assuming argument names. If a live route is unavailable, use an authorized narrow file edit on a fresh closed-deck copy through the existing project workflow; do not rebuild the deck or silently switch targets. No new bridge, API key or software installation is required by this skill.

Save and read back the notes at the actual slide locations, checking the current script and retained author material. Verify the saved file, visible slide content/order and the checks required by doc-slides after a PPTX edit. A tool success alone does not prove correct notes. Report unavailable native verification or unsupported operations; do not claim a native PowerPoint check from a file-only inspection.

Keep delivery cues and technical reminders explicitly non-spoken in notes too. Important conditions must remain in the spoken passage. Preserve the project's recovery point, and clean only owned temporary artifacts using the existing build-lifecycle rules.
