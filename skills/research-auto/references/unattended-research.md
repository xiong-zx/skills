# Continuous and unattended research

Read this only for explicitly authorized sustained or unattended work. It extends the cycle count while preserving the agreed goal, permissions, resources and stopping condition.

## Set a bounded plan

Recover the approved overall goal, the advance sought during this run, baseline, available window, allowed methods and useful outputs. Plan a multi-stage program with complementary modules, concrete opening packages, coarse later branches and room for independent verification and integration. Agents may explore different routes inside the authorized agenda. The first worker package is not the whole night's goal; completing it should reveal what to do next across the remaining program.

After each substantive exploration round, apply the supervision reference's direction assessment: compare the actual result with the original goal, identify any deviation, judge whether its scientific benefit justifies it, and revise the next stage. Preserve a justified supporting route with a return condition; redirect a detour that no longer advances the agenda. A scheduled wake is a continuation of this program, not a fresh assignment or a reason to repeat completed work. Use the user's actual window or stage boundary; do not invent a deadline or numerical spending cap.

A deadline is the latest stop, not a minimum runtime. Do not consume the whole window merely to keep a schedule active. Conversely, a first result or completed first cycle is not a reason to stop while useful authorized main work remains. Respect an explicit request to monitor a changing external state; identify which event could matter.

## Continue, wait, or hand back

At a substantive cycle boundary or necessary scheduled wake, recover the actual current action from the existing project state and choose:

1. **Stop condition reached or explicit pause:** stop new dispatches and any active research workers, save actual partial results, and pause the existing continuation through the supported product tool. Confirm its saved state.
2. **Candidate or review ready:** inspect the actual returned work, perform the required independent review or consequential repair, integrate its effect on the main conclusion, then choose the next action. A worker's return is not acceptance; do not wait for a clock tick to process it.
3. **Work genuinely running:** preserve its task and write scope. Advance an independent useful authorized obligation or use available completion messages/waits. Quiet work is not failure; do not redispatch it or demand periodic summaries merely to show activity.
4. **No worker or candidate pending:** assess the remaining approved program across its modules and directions, including deferred branches whose dependencies may now be available. If a valuable next complete question fits the mandate and resources, proceed. A known result, one finished module or uncertainty between ordinary candidate models is not by itself a reason to end the whole run. Lack of a prewritten task name is not lack of authorization.
5. **No useful authorized next action anywhere in that program, and no actionable expected event:** save the scope reached, remaining gap and recommendation, hand back once, and pause the existing recurring continuation now. Do not leave an empty loop active solely to turn it off at the deadline. Keep the broader goal open if unfinished.

When a user decision blocks progress, name the exact change that needs it. An ordinary example, parameter choice or proof tactic within the agreed mandate is usually the supervisor's job. If useful independent authorized work remains, continue it while awaiting the decision. A user request to approve a new plan still blocks work dependent on that plan; do not silently change the goal, information, metric, material model or resources.

## Schedule only an actionable check

Use the supported continuation mechanism already authorized by the user. Every planned wake needs an active object or a credible event that could change the next action, and a useful action if it occurs. Keep those in the existing next-action record, not a new dashboard or periodic log.

- Prefer completion messages and waits within an active turn. Do not assume a completed worker can automatically start a new parent turn unless that capability is verified. Use a scheduled fallback only where needed for actual pending work or stop protection.
- Respect an explicit user cadence. Otherwise align fallback checks with meaningful checkpoints and back off when unchanged work is progressing normally. Do not force a fixed hourly ritual or end useful work merely to fit one.
- An unchanged check should not reread the whole archive, repeat old agent summaries, rewrite STATUS, or notify again. A no-change check while a worker is running is waiting, not a failed research cycle. If the waiting object has disappeared, reassess the main dependency and pause when no useful action remains. Silence alone does not avoid model-call cost.
- Keep the scheduled prompt a short authorization and recovery contract: project, approved plan/current-state pointers, stop condition, resource limits and continuation/early-stop rules. Keep mutable findings, proof hashes, historical task summaries and current ACTIVE/PAUSED assertions in their authoritative records, not in the fixed prompt.

Do not invent a new daemon, cron, chat, cross-chat message or external delivery to implement this design. Report a capability limitation rather than claiming unattended persistence or precise stop timing that the available runtime cannot provide. Plan worker checkpoints and review reserves so a late fallback wake does not become permission to work past the cutoff.

## Preserve scientific value and evidence

Apply the supervision reference's goal checkpoint before dispatch, on substantive findings or changed scope, and after review. Retain useful checked intermediate results and return to main obligations. Necessary lemma chains may continue; repeated auxiliary polishing without a main-dependency or decision change triggers the existing correction procedure.

Do not fill unused time with larger numerical budgets, exact constants, same-benchmark rankings or unchanged retries. Diagnose inflated thresholds and accumulating assumptions at the mechanism/scale level first. Distinguish a checked result, a refutation, a scoped supporting fact and an open claim; none is measured by pages, elapsed time or task count.

## Stop and hand back

At a real stopping or hand-back condition, reconcile what can be verified and preserve unfinished claims as unfinished. Use the common reporting method linked from supervision: briefly restore context and state the main outcome and important open issue. Keep route-by-route findings and abandoned attempts in the existing records rather than the final message. Pause the existing automation when ending its continuation and read back once; do not create a replacement or assume that a quiet final reply stops it.
